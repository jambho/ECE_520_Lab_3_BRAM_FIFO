# ECE 520/L Lab 3: BRAM FIFO

## Overview

This lab implements a FIFO in VHDL that uses Block RAM for its internal memory. The FIFO has a synchronous, active-high reset, registered output data with a `valid` flag, `full`/`empty`/`almost_full`/`almost_empty` status flags, a `data_count` output, and a configurable read latency of 1 to 8 clocks.

The design is verified with a self-checking VHDL testbench that reads its stimulus from a text file generated by a Python script. Tcl scripts create the Vivado project and run the simulation.

| Path | Description |
| --- | --- |
| `src/sc_fifo.vhd` | FIFO design (top-level entity `sc_fifo`) |
| `sim/tb_sc_fifo.vhd` | Self-checking testbench (`tb_sc_fifo`) |
| `sim/input_data.txt` | Test stimulus, one 16-bit hex word per line |
| `scripts/generate_test_data.py` | Generates `sim/input_data.txt` |
| `scripts/create.tcl` | Creates the Vivado project in `proj/` |
| `scripts/simulate.tcl` | Runs the behavioral simulation and copies `test_results.txt` to `sim/` |

Target: Zybo Z7-10 (`xc7z010clg400-1`), Vivado 2023.2.

## Design Summary

### Interface

| Generic | Description | Default |
| --- | --- | --- |
| `WIDTH` | Data width in bits | 16 |
| `DEPTH` | Number of words the FIFO can store (power of two) | 32 |
| `ALMOST_EMPTY_THRESHOLD` | `almost_empty` is asserted at or below this many words | 1 |
| `ALMOST_FULL_THRESHOLD` | `almost_full` is asserted at or above this many words | 31 |
| `READ_LATENCY` | Clocks from an accepted read to `data_out`/`valid` (1 to 8) | 1 |

| Port | Direction | Width | Description |
| --- | --- | --- | --- |
| `clk` | in | 1 | Clock for both the write and read sides |
| `srst` | in | 1 | Synchronous, active-high reset |
| `data_in` | in | `WIDTH` | Write data |
| `write_enable` | in | 1 | Write request, ignored while full |
| `read_enable` | in | 1 | Read request, ignored while empty |
| `data_out` | out | `WIDTH` | Read data, registered |
| `valid` | out | 1 | High in the same cycle as valid `data_out` |
| `data_count` | out | `ceil(log2(DEPTH+1))` | Number of words stored, 0 through `DEPTH` |
| `full`, `empty` | out | 1 | Status flags |
| `almost_full`, `almost_empty` | out | 1 | Threshold warning flags |

### Architecture

- **Memory.** The storage is a Block Memory Generator IP instance (`blk_mem_gen_0`) configured as a simple dual-port RAM, 16 bits wide and 32 words deep. Port A is the write port and port B is the read port, both on `clk`. The FIFO Generator IP is not used.
- **Pointers.** `wr_ptr` and `rd_ptr` are `log2(DEPTH)`-bit counters that wrap naturally because `DEPTH` is a power of two. `wr_ptr` advances on an accepted write and `rd_ptr` on an accepted read.
- **Request qualification.** `wr_ok = write_enable and not full and not srst` and `rd_ok = read_enable and not empty and not srst`. Overflow and underflow requests are dropped here, so they never change the pointers, the count, or the memory.
- **Simultaneous read and write.** Both requests are qualified independently. When full, only the read is accepted; when empty, only the write is accepted; otherwise both are accepted and the count is unchanged.
- **Count and flags.** A separate `count` register of `ceil(log2(DEPTH+1))` bits tracks occupancy instead of comparing the pointers, which removes the full/empty ambiguity when the pointers are equal. The four flags are registered and computed from the next count value, so they change on the same clock edge as `data_count` and are glitch-free.
- **Registered output.** The BRAM's synchronous read is the baseline output register (`READ_LATENCY = 1`). Port B is enabled only by `rd_ok`, so `data_out` holds its value between reads. `srst` drives the BRAM's `rstb`, which returns the output register to 0 on reset without clearing the memory contents.
- **Read latency.** For `READ_LATENCY > 1`, `mem_dout` passes through `READ_LATENCY - 1` extra register stages. `valid` is `rd_ok` delayed through a `READ_LATENCY`-stage shift register, so it lines up with `data_out` for any setting. The count and flags do not go through the pipeline and always reflect the current state of the FIFO.
- **Reset.** While `srst` is high, the pointers, count, valid pipeline, and data pipeline are cleared, `empty` and `almost_empty` are set, and `full` and `almost_full` are cleared.

## Verification and Results

### Testbench

`tb_sc_fifo` uses a 50 MHz clock (20 ns period) and an active-high reset. It loads `input_data.txt` into an array and keeps a reference model of the FIFO: the index of the next word to write, the index of the next word expected on `data_out`, and the expected word count. After every clock cycle it checks:

- `data_out` equals the next expected word whenever `valid` is high, so data must come out in the order it was written.
- `data_out` does not change while `valid` is low.
- `data_count`, `empty`, `full`, `almost_empty`, and `almost_full` match the expected count.

Rejected writes drive `0x1234`, a value that is not in the pattern data, so an overflow write that was wrongly accepted shows up as a data mismatch. Each failure is logged with a timestamp to the console and to `test_results.txt`, and the run ends with `TEST PASSED` or `TEST FAILED: N errors`.

### Test Cases

| # | Test case | What it checks |
| --- | --- | --- |
| 1 | Reset at start-up | `data_out` = 0, `valid` = 0, `data_count` = 0, `empty` = 1, `full` = 0 |
| 2 | Fill with `0xFFFF`, then drain | All 1s through every memory location |
| 3 | Overflow | A write while full is ignored |
| 4 | Underflow | A read while empty is ignored |
| 5 | Fill with `0x0000`, then drain | All 0s through every memory location |
| 6 | Fill with alternating `0xAAAA`/`0x5555`, then drain | Alternating bit patterns |
| 7 | Fill with a unique word per location (`i xor 0xAAAA`), then drain | Every memory location is written and read back, with no address aliasing |
| 8 | Status flags | Checked every cycle of tests 2 to 7, so each flag is checked at every count from 0 to 32 |
| 9 | Walking ones, 16 words | Write one word, read it back on the next cycle |
| 10 | Reset in the middle of operation | Output returns to 0 after a non-zero word was read |
| 11 | Simultaneous read and write while empty | Only the write is accepted |
| 12 | Simultaneous read and write while full | Only the read is accepted |
| 13 | Simultaneous read and write while half full, 32 cycles | Count stays at 16 and data order is preserved |
| 14 | Final drain | Every word written was read out exactly once |

`write_enable` and `read_enable` are exercised alone, together, and both low (idle cycles after each drain).

### Test Data

`scripts/generate_test_data.py` writes 144 pattern words (32 of `0xFFFF`, 32 of `0x0000`, 16 pairs of `0xAAAA`/`0x5555`, 32 unique words, 16 walking ones) followed by `n` random 16-bit words (default 20, fixed seed 42). The testbench generic `NUM_RANDOM` must match `n`.

### Results

Behavioral simulation was run with Vivado 2023.2 (xsim) on October 26, 2026, using `src/sc_fifo.vhd`, `sim/tb_sc_fifo.vhd`, the `blk_mem_gen_0` simulation model, and the default `input_data.txt` (144 pattern words plus 20 random words).

| `READ_LATENCY` | How it was run | Simulated time | Result |
| --- | --- | --- | --- |
| 1 | Vivado project (`sim_1`) | Not recorded | `TEST PASSED` |
| 1 | `xelab -generic_top READ_LATENCY=1` | 8000 ns | `TEST PASSED` |
| 2 | `xelab -generic_top READ_LATENCY=2` | 8100 ns | `TEST PASSED` |
| 3 | `xelab -generic_top READ_LATENCY=3` | 8200 ns | `TEST PASSED` |
| 8 | `xelab -generic_top READ_LATENCY=8` | 8700 ns | `TEST PASSED` |

Every run ends with `TEST PASSED` and has no `FAIL` lines in `test_results.txt`. Each step of `READ_LATENCY` adds 5 clocks (100 ns), one idle cycle after each of the four drains and one at the end, which confirms that the generic reached the design.

| Check (every cycle, all runs) | Result |
| --- | --- |
| `data_out` equals the next expected word whenever `valid` is high | Pass |
| `data_out` holds its value while `valid` is low | Pass |
| `data_count`, `empty`, `full`, `almost_empty`, `almost_full` match the expected count, 0 to 32 | Pass |
| Write while full and read while empty are ignored | Pass |
| Simultaneous read and write at empty, full, and half full | Pass |
| `data_out` = 0 and `valid` = 0 after the start-up and mid-operation resets | Pass |
| Every word written is read out exactly once | Pass |

Two changes were needed to reach this result. The IP was regenerated without its safety circuit (`EN_SAFETY_CKT = false`), which had been forcing a read of address 0 after each reset. Port B's enable was also changed from `rd_ok` to `rd_ok or srst`, because `rstb` only clears the output latch while the port is enabled.

Synthesis and implementation were last run on October 12, 2026, before these two changes, so their utilization and timing reports do not describe the current design and are not included. There is no XDC file, so a rerun would still give no timing slack or maximum frequency.

## Known Issues or Limitations

**Functional issues:**
- The design is only parameterized on paper. The `blk_mem_gen_0` component is fixed at 16 data bits and 5 address bits, so `WIDTH` and `DEPTH` only work at their defaults. An inferred BRAM would fix this.
- The testbench hard-codes `DEPTH`, the thresholds, and a 6-bit `data_count`, and only passes `READ_LATENCY` to the FIFO. Other parameter values are not tested.
- This program somehow is coupled to my Onedrive instace on the blk_mem_gen_0 ip instance and cannot run without the file, I couldn't figure out how to swap it in without breaking the program.
